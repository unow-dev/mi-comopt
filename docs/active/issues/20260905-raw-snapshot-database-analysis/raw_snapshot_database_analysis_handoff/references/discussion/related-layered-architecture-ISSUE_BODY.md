# レイヤーモデルによるアーキテクチャ整理

## 目的

プロジェクト内の責務と依存関係を明確にし、データの収集、保存、加工および表示をそれぞれ変更・検証しやすい構成に整理する。

## 背景

本プロジェクトには、TikTok等の外部サービスからのデータ取得、収集データの保存、フィルターキーワードに関する加工・判定、および利用者への表示という異なる責務がある。これらが同じ場所に混在すると、外部サービスやデータベースの変更が加工ロジックやUIへ波及しやすく、責務ごとのテストや将来的な置き換えも難しくなる。

責務をレイヤーとして分離し、外部の形式や実装詳細は境界で変換することで、各領域を独立して扱いやすくする。

## 決定済みの大枠

- コレクター層、データベース層、データ加工層およびUI層の責務を分離する。
- アダプタは全レイヤー間に一律で設ける独立層とはせず、UI、外部サービスおよびデータベースなど、形式や実装詳細を隔離すべき境界で利用する。
- 各責務はディレクトリ単位で分離し、依存関係が把握しやすい構成にする。
- データ加工層はUI、データベースおよび外部サービスの具体的な実装詳細に依存しないようにする。
