# Comment DB更新時の過去データ継承

## 目的

Comment DBのデータ更新時に、既存のコメントデータを保持したまま新しいコメントデータを統合し、過去データと更新データの両方を含む一貫したcorpusを生成できる状態にする。

現行corpus、分類結果、キーワード候補、アカウント候補および公開用artifactが、承認された統合データを正本として生成され、更新前後のデータ範囲とsnapshotの対応関係を追跡できる状態を実現する。

## 背景

2026年9月21日の更新では、旧comment-batchの24,622件がDB内のraw入力および旧corpus versionに保持されている一方、現行Releaseのcorpusは新しく取り込んだ11,768件のsnapshotだけを参照していた。そのため、公開されたsource datasetも更新分の11,768件だけになり、旧データと更新データを累積した公開状態になっていない。

現在のv3更新処理では、入力されたcomment-batchから新しいsnapshot参照を作成し、corpus更新時に旧corpusのsnapshot参照を引き継がず、新しいsnapshot参照だけで次のcorpus stateを作成している。旧データそのものは削除されていないが、現行corpusの参照対象から外れるため、後続の分類、候補生成、Release作成およびWeb公開にも旧データが含まれない。

また、更新入力が「全量snapshot」なのか「追加分」なのか、過去データを保持して統合するのか、置換するのかというデータ更新の意味が運用上明確に区別されていない。更新単位ごとのデータ範囲、重複排除、既存ラベルの継承および公開対象の整合性を明確にし、意図しないデータ欠落を防ぐ必要がある。
