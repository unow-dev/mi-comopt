# ラベリングを含む候補キーワード生成フロー

## 目的

未ラベルのコメントデータを起点として、ChatGPTが3-classラベリングを担当し、ラベリング済みdatasetを候補キーワードの提案・評価・更新フローへ接続できる状態にする。

ラベリング結果について、判定基準、データ契約、品質確認、完了状態および上流データとの対応関係を追跡可能にし、ラベリングから候補キーワードの更新・公開までを一貫した運用として扱えるようにする。

## 背景

現在の候補キーワード更新フローおよびChatGPT手動handoffは、`direct_nuisance`、`reactive`、`normal` のいずれかが付与されたラベリング済みdatasetを入力として想定している。実装済みのdataset検証も、各レコードのラベル、公開済み状態、レコード数および必要なラベル件数を確認するだけであり、未ラベルのコメントを分類する処理は含んでいない。

そのため、現状の運用では、候補キーワードの提案を開始する前に、別の場所・別の手順でラベリングを完了し、結果を所定のdataset形式へ変換して配置する必要がある。この前段工程の責務、ラベル判定の根拠、品質確認の方法、ラベリング完了の判定およびdatasetの出所を、候補キーワード更新フローから一貫して確認することができない。

また、現在のChatGPT手動handoffが扱うのはラベリング済みデータを利用した候補キーワードの意味的提案であり、コメント自体のラベル付けやラベルの修正は対象外である。このIssueでは、ChatGPTをラベリング工程の担当として明示的に位置付け、未ラベルデータに対するラベル付与、ラベリング済みdatasetの生成および候補キーワード提案を一連のChatGPT作業として扱う。未ラベルデータから候補キーワードの更新・公開までを成立させるには、ChatGPTによるラベリング結果を品質確認・契約検証の境界を通して既存の候補生成・評価・publicationへ安全に引き渡す必要がある。
