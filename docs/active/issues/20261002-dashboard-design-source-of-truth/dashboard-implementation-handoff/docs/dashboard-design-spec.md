# ダッシュボード デザイン正本

## 1. 目的・位置づけ

現行のサービス紹介ホームを、コメント欄の状態と対応候補を短時間で把握するためのダッシュボードへ置き換える。

ダッシュボードは起動後に最初に見る「ホーム」であり、詳細分析画面ではない。分析の根拠・分類内訳・日次推移は「分析概要」に委ねる。

この文書をダッシュボードUIのデザイン正本とする。ラフ画像、issue上の過去コメント、現行UIと本文書が矛盾する場合は、公開データ契約に反しない限り本文書を優先する。

## 2. 画面の役割

### ホーム / ダッシュボード

目的:
- 選択期間のコメント欄の状態を要約する。
- 現在公開されている対応候補数を示す。
- 詳細分析・候補画面への入口になる。

表示するもの:
- 期間切替: 7日 / 30日
- 集計期間
- データ基準日
- 治安指数
- 評価
- 一次迷惑率
- 対象観測数
- coverage（部分観測時のみ明示）
- 状態コメント
- フィルターキーワード候補件数
- ブロックアカウント候補件数
- 「分析概要を見る」導線

### 分析概要

目的:
- ホームで見た状態の根拠を掘る。
- 分類内訳、日次推移、詳細な観測情報を確認する。

分析概要では `1日 / 7日 / 30日` を選択可能とする。

## 3. ナビゲーション

トップレベルの5画面構成は維持する。

| screen id | ナビ表示 | 補助表示 |
| --- | --- | --- |
| `home` | ホーム | 状態と対応候補 |
| `overview` | 分析概要 | 分類と推移 |
| `comments` | コメント一覧 | 対象観測 |
| `keywords` | フィルターキーワード候補 | 推奨度確認 |
| `accounts` | ブロックアカウント候補 | 候補判定 |

ホームのページHeader表示名は **「ダッシュボード」** とする。

ホームには戻るボタンを表示しない。他画面のホームへ戻る導線は現行挙動を維持してよい。

モバイルのホームHeaderもロゴ置換ではなく **「ダッシュボード」** と表示する。

## 4. データソース

### release root / manifest

候補件数には以下を使用する。

- フィルターキーワード候補: `release.artifacts.keywords.record_count`
- ブロックアカウント候補: `release.artifacts.accounts.record_count`

### overview artifact

ホームの状態表示にはoverview artifactを使用する。

- `overview.data_end_date`
- `overview.periods['7d']`
- `overview.periods['30d']`

期間内では以下を参照する。

- `start_date`
- `end_date`
- `coverage`
- `observation_count`
- `counts.direct_nuisance`

治安指数と一次迷惑率は既存 `derivePublicOrderIndex()` と既存formatterを使用する。

### ホーム初期表示時の取得制約

release root取得後、**ホーム表示のためにネットワーク取得してよいartifactはoverviewのみ**。

以下はホーム表示を理由に先読みしない。

- `keywords`
- `accounts`
- `comments`

候補行を開いた後、それぞれの既存画面で必要なartifactを取得する。

## 5. 期間仕様

### ホーム

- 選択肢: `7d`, `30d`
- 表示文言: `7日`, `30日`
- 初期値: `7d`

### 分析概要

- 選択肢: `1d`, `7d`, `30d`

### 画面間の状態共有

期間はホームと分析概要で共有する。

| 操作 | 遷移後 |
| --- | --- |
| ホーム7日 → 分析概要 | 7日 |
| ホーム30日 → 分析概要 | 30日 |
| 分析概要7日 → ホーム | 7日 |
| 分析概要30日 → ホーム | 30日 |
| 分析概要1日 → ホーム | 7日に正規化 |

分析概要1日からホームへ移動した場合、表示だけでなく共有state自体を `7d` に変更する。

期間はユーザー設定として永続化しない。ページ再読込後は7日から開始する。

## 6. 日付・期間表示

「今日」「リアルタイム」という表現は使用しない。

主要見出し:

> コメント欄の状態

日付フォーマット:

- `YYYY-MM-DD`

例:

- `データ基準日: 2026-09-20`
- `集計期間: 2026-09-14 — 2026-09-20`

`データ基準日` は `overview.data_end_date`。

`集計期間` は選択中periodの `start_date — end_date`。

## 7. 治安指数カード

### 主表示

- 見出し: `治安指数`
- 治安指数: 既存 `formatPublicOrderScore()` の結果
- 単位: `/ 100`
- 評価ラベル:
  - `goal_met` → `目標達成`
  - `goal_unmet` → `目標未達`
  - `caution` → `注意`
  - `warning` → `警告`
  - `unavailable` → `算出不可`
- 一次迷惑率: 既存 `formatDirectNuisanceRate()` の結果
- 対象観測数: `period.observation_count` を `ja-JP` の3桁区切りで表示し `件` を付ける

### ゲージの意味

ゲージは「治安指数の0〜100ゲージ」ではなく **一次迷惑率の評価境界** を表す。

目盛り:

- 0%
- 2%
- 3%
- 4%
- 6%

6%以上のマーカーは右端にクランプする。

評価境界:

| 一次迷惑率 | evaluation | 表示 |
| --- | --- | --- |
| `<= 2%` | `goal_met` | 目標達成 |
| `> 2% && < 3%` | `goal_unmet` | 目標未達 |
| `>= 3% && < 4%` | `caution` | 注意 |
| `>= 4%` | `warning` | 警告 |

既存の色体系を維持してよいが、**色だけで評価状態を伝えない**。必ず評価文字列を併記する。

### 算出不可

`observation_count === 0` の場合:

- 治安指数: `— / 100`
- 評価: `算出不可`
- 一次迷惑率: `—`
- 対象観測数: `0件`
- ゲージマーカー: 非表示

これはエラーではなく正常な算出不可状態。

## 8. coverage

`period.coverage === 'partial'` の場合、部分観測を明示する。

表示:

> 部分観測

補足文:

> 一部の日付にデータがないため、取得できたデータのみで集計しています。

`complete` の場合は部分観測の警告を出さない。

## 9. 状態コメント

正式なマスコット画像は今回の実装条件にしない。カード名は **「状態コメント」** とする。

文章は自由生成せず、評価値から決定論的に生成する。

| evaluation | 文言 |
| --- | --- |
| `goal_met` | `一次迷惑率は {rate} で、目標範囲内です。現在は落ち着いた状態です。` |
| `goal_unmet` | `一次迷惑率は {rate} で、目標値を上回っています。分析概要で推移を確認してください。` |
| `caution` | `一次迷惑率は {rate} で、注意が必要な水準です。分析概要で内訳と推移を確認してください。` |
| `warning` | `一次迷惑率は {rate} で、警告水準です。対応候補もあわせて確認してください。` |
| `unavailable` | `対象観測がないため、治安指数を算出できません。` |

`{rate}` には既存formatterの表示結果をそのまま使う。

partial時の補足は状態コメント本文に混ぜず、coverage情報として別表示する。

## 10. 対応候補

セクション名:

> 対応候補

補足:

> AI分析から抽出された、確認対象の候補です。

表示行:

- `フィルターキーワード候補    N件  >`
- `ブロックアカウント候補     N件  >`

件数は選択期間に連動しない。manifestで公開されている現在の候補全件数を表す。

0件でも行を表示し、遷移可能とする。

ホームでは `NEW` バッジを表示しない。

候補行を開いた際:

- 検索条件を自動設定しない
- NEW filterを自動設定しない
- 特定候補を自動選択しない
- 一覧の通常初期状態を表示する

## 11. 分析概要への導線

治安指数カード末尾に明示的なCTAを置く。

ラベル:

> 分析概要を見る

カード全体をクリック可能にはしない。

右向き矢印アイコンは使用可。

遷移時は7日/30日の共有期間を維持する。

## 12. Loading / Error

### アプリ初期起動

現行のrelease root取得と `INITIAL_LOADING_MINIMUM_MS = 2000` は今回変更しない。

### ホーム / overview

release root取得完了後はホーム骨格を表示する。

即表示可能:

- Header
- 期間切替
- manifest由来の対応候補件数

overview領域のみ非同期状態を持つ。

ホームのoverview取得には、既存artifact画面で使われている700msの人工最低loading時間を適用しない。

### overview取得失敗

画面全体をエラーにしない。

治安関連領域のみ:

> コメント欄の状態を読み込めませんでした。
> [再試行]

- 候補件数は継続表示する。
- 再試行はoverviewだけを再取得する。
- エラー領域は `role="alert"`。

release root自体の取得失敗挙動は今回変更しない。

## 13. データ基準日の状態

overview取得成功時に `overview.data_end_date` をApp階層の表示状態へ反映する。

overview取得前は:

> データ基準日: —

overview取得後、他画面に移動しても最後に正常取得した値をHeaderに保持する。

## 14. レスポンシブ

既存の `820px` 境界を維持する。

### `> 820px`

- 左サイドバー
- 治安指数カードと状態コメントを2カラム配置可能
- 対応候補はその下で全幅

### `<= 820px`

- 下部固定ナビ
- ダッシュボード内容は1カラム
- 横スクロールを発生させない

情報順序は画面幅にかかわらず次を守る。

1. ページタイトル + 期間切替
2. 集計期間 / coverage
3. 治安指数
4. 状態コメント
5. 対応候補

## 15. アクセシビリティ

最低要件:

- 期間切替コンテナ: `role="group"`, `aria-label="分析期間"`
- 期間ボタン: `aria-pressed`
- 主要クリック対象: 最低44px高
- 対応候補行: キーボード操作可能なbutton相当要素
- 一次迷惑率ゲージ: `aria-hidden="true"`（同内容を文字でも提示する）
- 色だけで評価を区別しない
- overviewエラー: `role="alert"`
- loading中の治安関連領域: `aria-busy="true"`
- 既存focus-visible表現を維持
- モバイル下部ナビの現在地: `aria-current="page"`

## 16. 実装側の裁量

正本に拘束されるもの:

- データの意味
- 表示項目
- 期間仕様
- 状態・エラー・遷移
- 情報構造
- accessibility要件
- artifact取得制約

実装者に任せるもの:

- コンポーネント名
- ファイル分割
- hooksの切り方
- CSS実装方式
- 数px単位の余白
- 内部state実装方式（外部挙動は正本準拠）
- テストファイル構成

## 17. 対象外

今回変更しないもの:

- 正式マスコットアート制作
- 候補の確認済み / 未確認状態の新設
- サーバー側状態保存
- 候補状態の端末間同期
- 治安指数算式
- 評価閾値
- 公開artifact schema
- 分析概要の日次グラフ再設計
- 初期2秒起動演出
- コメント一覧 / 候補詳細のデータ解釈

## 18. Freezeルール

次の場合のみ仕様へ戻す。

- 公開データ契約上実現できない
- 既存画面との意味的矛盾が発見された
- accessibility要件を満たせない
- 受け入れ条件同士が衝突する
- 明確な性能問題が発生する

「別の実装の方が書きやすい」「コードがきれいになる」は仕様変更理由にしない。
