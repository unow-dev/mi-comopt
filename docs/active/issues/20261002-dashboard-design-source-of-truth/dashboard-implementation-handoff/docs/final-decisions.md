# 最終採択事項

この文書は設計議論の結果を短く確認するためのサマリーです。実装仕様の詳細は `dashboard-design-spec.md` を優先してください。

## 採択

1. ダッシュボードを新しいホームにする。
2. ホームの期間切替は7日 / 30日。
3. 初期期間は7日。
4. 分析概要は1日 / 7日 / 30日を維持する。
5. ホームと分析概要で期間stateを共有する。
6. 分析概要1日からホームへ戻る場合は7日に正規化する。
7. ホームは「要約」、分析概要は「根拠・推移」という役割分担にする。
8. 「今日」「リアルタイム」は使わない。
9. データ基準日はoverview.data_end_date。
10. ホームではoverview artifactだけを取得する。
11. 候補件数はmanifestのrecord_countを使う。
12. 候補件数は期間切替に連動しない。
13. ホームにNEWバッジを表示しない。
14. 状態コメントはevaluationから固定文言を生成する。
15. 正式マスコット画像は必須にしない。
16. ゲージは一次迷惑率の評価境界を表す。
17. 対象件数の表示名は「対象観測数」。
18. partial / unavailable / overview errorを別状態として扱う。
19. overview errorでも候補件数は表示する。
20. `820px` の既存レスポンシブ境界を維持する。
21. ホームHeaderは「ダッシュボード」。
22. ホームに戻るボタンは置かない。
23. current bottom navigationにaria-currentを追加する。
24. 現行screen state方式を維持可能。新routerは要求しない。
25. 内部コンポーネント構造は実装者裁量。

## 明示的に撤回された旧案

以下は途中で検討されたが、最終仕様ではない。

### 撤回: ホームでoverview / keywords / accountsを並列取得

最終:
- overviewだけ取得する。
- keywords/accounts件数はmanifestから読む。

### 撤回: 候補領域ごとのartifact loading/error/retry

最終:
- ホームではkeywords/accounts artifactを取得しないため不要。

### 撤回: ホームのキーワード候補にNEWバッジ

最終:
- ホームではNEWを出さない。
- 詳細候補画面側の既存NEW概念は変更しない。

### 撤回: DashboardRoute必須

最終:
- 現行 `screen` 切替構造で実装してよい。

### 撤回: ラフ画像のマスコットをそのまま製品素材として使用

最終:
- マスコット画像なしで状態コメントカードを成立させる。
