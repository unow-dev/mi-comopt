# Issue: ChatGPT向け3-class判定セットを簡素化する

## 目的

プロンプト、判定ルール、過去の判定結果、および追加判定対象を一つの作業セットに同梱し、ChatGPTが追加分を判定して判定結果を返却できる、シンプルで明確な受け渡し状態にする。

## 背景

現在の`three-class-workset`は、ChatGPTが判定に使用するプロンプト・判定対象・過去判定の文脈に加えて、既存pipelineのworkspace、snapshot、provenance、manifest、ZIP、finalize用の管理情報まで一体として扱っている。これにより既存処理との互換性や入力の整合性は確保できる一方、ChatGPTへ渡す判定用のセットと、ローカル側で必要な運用・監査用の情報が混在し、返却物の配置や受け渡し方法が分かりにくくなっている。

必要なのは、ChatGPTが判定に必要なプロンプト、判定ルール、過去の判定結果、追加判定対象を一つのセットとして受け取り、追加分の判定結果だけを返却できる明確な受け渡しである。現状はこの目的に対して周辺のpipeline契約が前面に出ており、判定作業そのものの入力と返却の境界を簡潔に示せていない。

## 方針

設計対象を、ChatGPTへ提供する判断材料と、ChatGPTから受け取る判定結果の契約に限定する。ChatGPT内部の判定手順、推論、処理単位、処理方式は規定せず、ブラックボックスとして扱う。ローカル側では、判断材料の完全性と返却物の形式・対象対応を契約として確認できる状態だけを定義する。
