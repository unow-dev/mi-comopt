# Issue: rich raw入力のDB保持とsource of truth化

## 目的

rich raw入力全体をデータとしてDBに保持し、後続処理が外部のrawファイルや途中の非可逆な投影に依存せず、DBから必要なデータを取得できる状態にする。v1.5分類処理については、DB上のrich rawデータから必要な5フィールドを取得して既存の入力契約へ渡せる状態を実現し、入力全体の保持と下流処理の互換性を両立する。

## 背景

実更新用の`new-comments.json`は、複数のスナップショットとコメント情報を含むrich wrapper形式で、動画・投稿者・取得状況などの情報も含めた入力全体が記録されている。一方、現行のraw importerは単一のスキーマ準拠スナップショットを前提としており、DBには正規化した一部の項目だけを保存し、入力バイト列はDB外のrawファイルとして保持している。

このため、入力全体をDBから再取得できず、rich rawに含まれる情報を利用する後続処理が外部ファイルの存在に依存する。また、v1.5分類処理が要求する`username`、`handle`、`comment`、`postedAt`、`postedDate`の5フィールドへ先に投影すると、その後に必要となるrich rawの情報へDBから戻れない。現在の実更新フローは、入力形式の変換だけでなく、入力全体を保持する場所と後続処理が参照するsource of truthの設計が一致していないため、継続利用できない状態になっている。
