# アカウントブロック候補リスト

## 目的

フィルターキーワードによるコメント単位の対策を補完し、ブロックを検討すべきアカウントを確認できる状態にする。

最終的に、UI上でアカウントブロック候補リストを表示し、利用者が候補を確認して手動でブロック判断を行えるようにする。

初期段階では、候補をUIに表示して確認できる最小限の範囲に絞ったMVPとして設計・実装する。

## 背景

現行のフィルターキーワード候補リストは、特定の本文表現を含むコメントを対象にするモデレーション手段である。しかし、同じアカウントが表記や文面を変えながら繰り返し迷惑行為を行う場合、キーワードだけでは継続的な対処として不十分になり得る。

特に、同一アカウントによる反復的な否定、嘲笑、性的対象化、スパムまたは勧誘は、個別コメントの非表示候補化に加え、アカウント単位での対応を検討する必要がある。フィルターキーワードとアカウントブロックを組み合わせることで、本文表現と行為者の両面からモデレーションを行えるようにする。

## 初期考察

- アカウントブロック候補は自動ブロックの対象ではなく、利用者が最終判断するためのレビュー対象として扱う。
- 初期実装はMVPとして、候補の生成・表示・根拠確認に必要な最小限の機能に限定し、候補の状態管理やブロック操作の自動化は後続の検討対象とする。
- アカウントの識別には、表示名ではなく同一性を判定できる `handle` を用いる必要がある。
- 候補化の根拠には、ラベル済みコメントにおける迷惑行為の件数、反復性、内容の種類および確認時点を利用できるようにする必要がある。
- 候補の表示では、候補化の理由を確認できることと、必要以上の個人情報や元コメントを露出しないことの両立を検討する。
- キーワード候補とアカウント候補は判断対象と必要なデータが異なるため、既存のキーワード候補フローへの単純な追加ではなく、責務とデータ境界を整理する必要がある。
