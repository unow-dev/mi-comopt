# Issue: Comment DBから3-class作業セットを直接生成する経路を追加する

## 目的

Comment DBに保存されたコメントデータを対象に、対象スナップショットを指定して、作業者であるChatGPTがそのまま3-class分類作業を開始できる作業セットを一度のコマンド実行で生成できる状態にする。

DB上の対象レコードを再現可能な条件で選択し、元データの順序・重複・出典を保ったまま、ChatGPTによる作業に適した構成の入力・管理情報・補助ファイルを生成する。コマンド実行の最終成果物は、これらのファイル群を一つのzipにまとめたものとし、DBからファイルを手動で取り出して作業セットを組み立てる手順を不要にする。

## 背景

現在のComment DBには、旧5-field形式のコメントバッチを`comment-batch`として取り込み、スナップショット単位で読み取る仕組みがある。また、`export-analysis-input`コマンドによって、DBから5-field JSONとmanifestをファイルへ書き出すこともできる。

一方、3-class分類の作業フローは、`docs/active/operations/Integrated_Labeling_Handoff_v1.5.0/src/pipeline.py`がファイル形式の入力を受け取る構成になっている。Stage13の準備・確定を経て3-class候補やレビュー用ファイルを生成する処理は存在するが、Comment DBのスナップショット選択から作業セット生成までを一つのコマンドで接続する実装はない。

そのため現状は、DBから対象データをエクスポートし、出力ファイルを既存パイプラインへ手動で渡したうえで、ChatGPTが扱うためのファイル構成を別途整える必要がある。この手順では、対象スナップショットの指定、元レコードの順序・重複、入力の出典情報が作業セットと分離しやすく、同じDB状態から同じ作業セットを再生成する経路も明確ではない。また、作業に必要なファイル群が個別に受け渡されるため、ChatGPTが作業開始時に参照すべき入力と補助情報を一つの成果物として扱いにくい。
