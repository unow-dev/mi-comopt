# UI上の派生値として治安指数を表示する

## 目的

選択期間に観測したコメント欄の状態を、総合スコアとしての「治安指数」と評価区分から把握できる状態にする。一次迷惑率、対象期間、対象観測数および既存の分類内訳とあわせて、評価の根拠を確認できる状態を実現する。

初期版の治安指数は一次迷惑率を換算した指標とし、導出ロジックを後から差し替えられる状態にする。

## 背景

現在の分析概要は、「通常」「二次反応」「一次迷惑」の3分類の件数・割合と日次推移を表示している。これらの内訳に加えて、コメント欄の状態をひと目で把握する入口として総合スコアを設けたい。

「治安指数」という名称は、「こちらコメント管理局！」「コメントパトロール」というサービスの世界観に合わせたものである。指数は、観測したコメント欄の平穏さを表す目安として位置付ける。

単純に一次迷惑率を100から引く換算では、例えば一次迷惑率5％でも95点となり、運用上の評価ラインと点数の印象が対応しにくい。そのため、目標値2％、注意ライン3％、警告ライン4％を前提に、各ラインと点数の対応を明示した換算を暫定採用する。

初期版は、既存の公開集計データからUI側で求める派生値として扱う。スコアの永続化や履歴管理を導入せずに表示を始め、必要に応じて導出ロジックを見直せる範囲とする。

## ここまでの採択案

### 1. 指数の意味と評価対象

- 名称は「治安指数」とする。
- 0〜100点で表し、高いほど観測したコメント欄が穏やかであることを示す。
- 初期版では、一次迷惑率を点数に換算する。複数の指標を重み付けした合成スコアにはしない。
- 評価対象と観測単位は、既存の分析概要の集計に合わせる。フィルター・ブロック適用後に実際に表示されているコメント欄の状態を表すものではない。
- 既存の1日・7日・30日の期間選択に連動させる。期間とデータ基準日は既存集計に従う。
- 二次反応率は分類内訳として扱い、独立した減点要素にはしない。二次反応には擁護や励まし、攻撃的な反論などが含まれるため、指数への組み込みは別途検討する。

### 2. 入力と一次迷惑率

選択期間の既存集計から、次の値を使用する。

| 記号 | 意味 | 既存集計上の値 |
| --- | --- | --- |
| `D` | 一次迷惑の観測数 | `period.counts.direct_nuisance` |
| `N` | 対象観測数 | `period.observation_count` |
| `p` | 一次迷惑率（％単位） | `100 × D / N` |

`N`は通常・二次反応・一次迷惑を含む対象観測数とする。二次反応を独立した減点要素にしないことは、分母から除外することを意味しない。

`p`は％単位の数値とし、例えば一次迷惑率3％の場合は`p = 3`とする。`N = 0`の場合は割合と指数を算出しない。

### 3. 目標値・注意ライン・警告ライン

| 一次迷惑率 | 評価 |
| --- | --- |
| `0 ≤ p ≤ 2` | 目標達成 |
| `2 < p < 3` | 目標未達 |
| `3 ≤ p < 4` | 注意 |
| `4 ≤ p` | 警告 |

目標値は2％以下、注意ラインは3％以上、警告ラインは4％以上とする。評価は表示用に丸める前の一次迷惑率から判定する。

### 4. 暫定の点数換算

次の対応点の間を直線で補間し、6％以上は0点とする。

| 一次迷惑率 | 治安指数 |
| --- | ---: |
| 0％ | 100 |
| 2％ | 80 |
| 3％ | 60 |
| 4％ | 40 |
| 6％以上 | 0 |

有効な観測数から得た一次迷惑率`p`に対する治安指数`S`は、次の式で表す。

```text
0 ≤ p ≤ 2 の場合:
  S = 100 - 10 × p

p > 2 の場合:
  S = max(0, 120 - 20 × p)
```

例えば、対象観測数1,000件・一次迷惑33件では、一次迷惑率は3.3％、治安指数は54点、評価は「注意」となる。

目標値2％を80点に置くことで、目標達成後の改善も点数に反映できる。この換算は初期版の暫定ロジックであり、将来の見直しを可能にする。

### 5. UI内の派生値と差し替え方針

- 既存集計を入力として、ブラウザ上で一次迷惑率・治安指数・評価を求める。
- 算出処理はUI側の独立した計算関数にまとめる。換算式や評価ラインを表示処理に埋め込まず、導出ロジックを差し替えられる構成とする。
- 期間選択の変更に応じて、その期間の集計から再計算する。
- スコア用のDB項目、公開JSON項目、保存APIは追加しない。ブラウザ内にもスコア履歴を永続化しない。
- 算出方式のバージョンの永続管理、過去スコアの保存・移行、前期間比較は初期版の対象に含めない。履歴保存や比較が必要になった段階で検討する。

### 6. 表示とデータ不足時の扱い

- 分析概要の期間切り替えの下、既存の3分類カードの上に、治安指数のカードを1枚配置する。
- カードには「治安指数」、100点満点の点数、「目標達成」「目標未達」「注意」「警告」の評価をシンプルに併記する。
- 一次迷惑率と目標値2％以下をカード内に表示する。
- 対象期間と対象観測数は既存の表示を共用し、期間切り替えに連動させる。指数で状態を把握し、その下の分類内訳や推移で理由を確認できる配置とする。
- 対象観測数0件の場合は「算出不可」とし、100点や「目標達成」とは表示しない。
- 既存集計で部分観測とされている場合は、観測できた範囲から算出し、「参考値」として表示する。
- 少数の観測については対象観測数を併記する案が出ているが、算出を制限する最低件数の要否・値は、ここまでの議論では確定していない。
- 具体的な色・表示桁数・端数処理は、ここまでの採択では固定していない。表示用の丸めによって数値と評価の境界が食い違って見えないよう、表示精度を設計する。

一次迷惑率3.3％の場合の表示例:

```text
治安指数  54 / 100  〈注意〉
一次迷惑率 3.3％ · 目標 2％以下
```
