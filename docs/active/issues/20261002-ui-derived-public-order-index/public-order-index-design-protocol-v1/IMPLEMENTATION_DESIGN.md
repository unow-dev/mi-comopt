# 実装設計 — 治安指数 UI

## 目的

分析概要に、選択期間の一次迷惑率を換算した代表指標「治安指数」を追加する。

初期版は複数指標の合成スコアではなく、一次迷惑率の単調変換とする。利用者がコメント欄の状態を短時間で把握できることを目的とし、特にモバイルで「期間 → 観測情報 → 治安指数 → 分類内訳 → 日次推移」の順に意味が追える構成とする。

## 不変仕様

### 指標の意味

- 選択期間について、一次迷惑件数 `D` は `period.counts.direct_nuisance`、観測数 `N` は `period.observation_count` を正本とする。
- `counts` の合計から `N` を再構成しない。
- `N >= 1` の一次迷惑率は、丸め前の値 `p = 100 * D / N`（%単位）とする。
- 評価は丸め前の `p` から次の境界で決める。

| p | evaluation | 表示 |
|---|---|---|
| `0 <= p <= 2` | `goal_met` | 目標達成 |
| `2 < p < 3` | `goal_unmet` | 目標未達 |
| `3 <= p < 4` | `caution` | 注意 |
| `4 <= p` | `warning` | 警告 |

- 治安指数 `S` は丸め前の `p` から次式で求め、計算途中では丸めない。

```text
0 <= p <= 2:
  S = 100 - 10 * p

p > 2:
  S = max(0, 120 - 20 * p)
```

- 評価とスコアは独立して `p` から決める。評価をスコアから逆算せず、表示用に丸めた値から評価を再判定しない。
- `N = 0` は正常な算出不能状態として扱い、指数・一次迷惑率・評価は値なしとする。
- 不正な `D / N` と `N = 0` を同一状態へ丸めない。
- `coverage` は治安指数・評価・スコアへ影響させない。`coverage === "partial"` でも観測できたレコードから通常計算する。
- 少数観測を理由に「参考値」へ変更しない。
- 二次反応率を治安指数の独立減点要素にしない。
- 評価基準とスコア曲線は別責務とする。将来スコア曲線が変わっても、評価ライン変更の要求がない限り上記評価境界を維持する。

### 既存挙動として維持する条件

- 初期選択期間は `7d` とする。
- `coverage === "partial"` の既存「部分観測」表示は維持する。
- 日次推移は既存の `overview.daily` 30日系列を表示し、期間切替には連動させない。
- 上部アプリヘッダーの画面名「分析概要」は維持する。
- 既存の固定ボトムナビとsafe-area対応を維持する。

### 変更しない外部・永続契約

今回の変更では、次を変更しない。

- DB
- 公開JSON schema / 公開JSON項目
- release manifest
- `src/ui/release-client.js` のartifact validator
- `src/processing/optimicom-ui-release/overview.js`
- `src/processing/optimicom-ui-release/release.js`
- ブラウザ永続状態
- スコア履歴の永続化
- 算式バージョンの永続管理
- 前期間とのスコア比較
- `coverage` データモデル

過去公開データを開いた場合も、保存済みスコアではなく、その時点のUI実装の算式で再計算する。

## 完了条件

### ドメイン計算

次の入力で結果が一致すること。

| D | N | p | score | evaluation/status |
|---:|---:|---:|---:|---|
| 0 | 0 | — | — | unavailable |
| 0 | 1 | 0% | 100 | goal_met |
| 1 | 1 | 100% | 0 | warning |
| 1 | 20 | 5% | 20 | warning |
| 20 | 1000 | 2% | 80 | goal_met |
| 30 | 1000 | 3% | 60 | caution |
| 40 | 1000 | 4% | 40 | warning |
| 60 | 1000 | 6% | 0 | warning |
| 61 | 1000 | 6.1% | 0 | warning |
| 33 | 1000 | 3.3% | 54 | caution |

境界直近は丸め前の生rateで評価されること。

```text
D=2001, N=100000 -> 2.001% -> goal_unmet
D=2999, N=100000 -> 2.999% -> goal_unmet
D=3000, N=100000 -> 3.000% -> caution
D=3999, N=100000 -> 3.999% -> caution
D=4000, N=100000 -> 4.000% -> warning
```

次は契約違反として `RangeError` になること。

```text
N < 0
D < 0
D > N
D または N が非整数
D または N が safe integer でない
```

### 表示フォーマット

一次迷惑率は少なくとも次を満たすこと。

```text
3.30%  / caution    -> 3.3%
2.53%  / goal_unmet -> 2.5%
2.04%  / goal_unmet -> 2.04%
2.96%  / goal_unmet -> 2.96%
3.96%  / caution    -> 3.96%
2.001% / goal_unmet -> 2.0%超
2.999% / goal_unmet -> 3.0%未満
3.999% / caution    -> 4.0%未満
```

治安指数は少なくとも次を満たすこと。

```text
54.0  / caution    -> 54
60.8  / goal_unmet -> 61
59.8  / caution    -> 60
39.8  / warning    -> 40
79.6  / goal_unmet -> 79.6
79.98 / goal_unmet -> 80未満
60.4  / goal_unmet -> 60.4
60.02 / goal_unmet -> 60超
40.4  / caution    -> 40.4
40.02 / caution    -> 40超
```

### UI統合

- 初期期間が `7d` であること。
- `1d / 7d / 30d` の切替で、選択periodの `D / N` から治安指数・評価・一次迷惑率が更新されること。
- 期間切替の選択状態がアクセシビリティAPIから判別できること。
- `D / N` の `N` に `period.observation_count` が使われ、`counts` 合計から再構成されていないこと。
- 日次推移が期間切替に連動せず、既存30日 `overview.daily` を維持すること。
- 同じ `D / N` なら `coverage=complete/partial` で指数結果が変わらないこと。
- `coverage=partial` の既存表示が観測情報欄に残ること。
- 治安指数カードに「参考値（部分観測）」を出さないこと。
- 少数観測でも参考値扱いしないこと。
- `N = 0` で `— / 100`、`算出不可`、一次迷惑率 `—` となり、ゲージmarkerが表示されないこと。
- 評価色だけでなく評価文字列が表示されること。
- 既存の重複した「3分類件数カード + 分類構成」を一つの分類内訳へ集約し、同内容を重複表示しないこと。
- 公開artifact・DB・ブラウザ永続状態へ治安指数値を保存しないこと。

### レスポンシブ / 操作性

- `2.0%超` / `3.0%未満` / `4.0%未満` の表示でカードが崩れない。
- 固定ボトムナビが最終コンテンツを隠さない。
- モバイルで治安指数・評価・一次迷惑率を主要な初期スクロール範囲から確認できる。
- デスクトップで分類内訳と日次推移を横並びにした場合も可読性を維持する。

### ゲージ

marker位置が次と一致すること。

```text
p=0   -> 0%
p=2   -> 33.333%
p=3   -> 50%
p=4   -> 66.667%
p=6   -> 100%
p>6   -> 100%へclamp
N=0   -> marker非表示
```

色区間の境界も同じ位置と一致すること。

## 確定設計

### 表示フォーマット

- 一次迷惑率と治安指数は、短い表示を優先しつつ、元の評価区分と矛盾する丸め表示にしない。
- 一次迷惑率は、小数1桁 → 小数2桁 → 評価境界の不等号表記の順に、元の評価区分を保てる最短表現を選ぶ。
- 治安指数は、整数 → 小数1桁 → 評価境界の不等号表記の順に、元の評価区分を保てる最短表現を選ぶ。
- `N = 0` の表示は、治安指数 `— / 100`、評価 `算出不可`、一次迷惑率 `—` とする。

### 情報構成

- 分析概要のページ内容は、モバイルで次の順序にする。
  1. 「コメント欄の状態」
  2. `1日 / 7日 / 30日` の期間切替
  3. 対象観測数・部分観測表示・対象期間
  4. 治安指数
  5. 分類内訳
  6. 日次推移
- 期間切替で更新するのは、観測情報・治安指数・分類内訳とする。
- `coverage === "partial"` は観測情報欄だけで示し、治安指数カード内に「参考値（部分観測）」等を追加しない。
- 既存の重複した「3分類件数カード + 分類構成」は一つの「分類内訳」へ統合する。
- 評価は色だけに依存せず、評価文字列も表示する。

### 計算責務の境界

- 治安指数の計算責務はUI表示責務から分離する。
- 計算側へ渡す入力は `directNuisanceCount` と `observationCount` の意味に限定し、`coverage`、期間キー、Reactオブジェクト、公開JSON全体を計算責務へ持ち込まない。
- 計算結果は、少なくとも `status`、丸め前の一次迷惑率、丸め前のscore、evaluationをUI側が参照できる契約にする。
- `N = 0` の `unavailable` と入力契約違反を区別する。前者は正常結果、後者は例外とする。
- 表示フォーマット責務は計算式そのものと分け、formatterがevaluationの意味を壊す丸めを行わない契約にする。

### UIとの境界

- `OverviewScreen` は選択periodから `D / N` を取り出し、計算責務へ渡す。period全体を計算責務へ渡さない。
- `coverage` は既存の期間状態表示だけに使用し、指数計算へ接続しない。
- 分類内訳でも観測数の正本を共有し、指数と分類割合で別の分母定義を作らない。
- 日次推移は選択periodとは別の30日系列という既存契約を維持する。
- 分類情報は、件数と割合を一つの「分類内訳」に統合し、同じ意味を別カードで重複させない。
- 既存アプリシェル、固定ボトムナビ、safe-area対応を再実装せず利用する。

### ゲージの責務

- ゲージは視覚補助であり、値の正本は一次迷惑率の数値テキストとする。
- ゲージは支援技術向けの値表現としては扱わず、数値テキストから意味を取得できるようにする。
- 実スケールは0〜6%とし、6%超は右端へclampする。
- 区間は評価境界と同じ `0〜2 / 2〜3 / 3〜4 / 4〜6` を使う。
- `N = 0` では0%位置にmarkerを置かず、marker自体を表示しない。

### 評価表示

- evaluation と表示ラベルの対応は `goal_met=目標達成`、`goal_unmet=目標未達`、`caution=注意`、`warning=警告`、`unavailable=算出不可` とする。
- 色は既存UIの意味体系を再利用し、`goal_met / goal_unmet / caution / warning / unavailable` が視覚上区別できること。ただし色のみを意味の正本にしない。

## 実装仮説

以下は探索開始点であり、実コード上の事実に応じて、上記の不変仕様・確定設計を壊さない範囲で変更してよい。

- `src/ui/public-order-index.js` を追加し、計算・rate formatter・score formatterを置く。
- 外部exportは `derivePublicOrderIndex`、`formatDirectNuisanceRate`、`formatPublicOrderScore` の3関数とする案が簡潔。
- `2 / 3 / 4 / 6` の閾値は同一モジュール内の名前付き定義へ集約する。
- `PublicOrderIndexCard` と `ClassificationBreakdown` は、再利用先が見つからなければ `App.jsx` のローカルコンポーネントとして実装する。
- 新しいグローバルbreakpoint体系は増やさず、既存の `820px` 境界を利用する。
- 既存Tailwind utilityで完結できるなら `index.css` は変更しない。
- unavailable用Pillは既存tone体系にgrayを追加する。既存トークンがなければ `#F1F4F7 / #6F7E91` 相当を候補とする。
- 治安指数カードの内部余白はモバイル約16px、デスクトップ約20pxを開始点とする。
- 日次推移の高さはモバイル約172〜180px、デスクトップ既存約220pxを開始点とする。
- 分類色は既存の `normal / reactive / direct_nuisance` の色表現を再利用する。
